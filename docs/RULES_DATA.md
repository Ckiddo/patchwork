## 已冻结的项目规则

| 内容 | custom_v1 定义 |
|---|---|
| 玩家与图版 | 2 人，各自 9×9；前端左对手、右自己，按身份映射 |
| 初始资源 | 每人 5 纽扣、1 个时间指示物；公共纽扣无限 |
| 外围方向 | 顺时针，中立指示物初始在 ID 10 的 1×2 拼布之前；至多后三块候选 |
| 同格 | 上一名普通行动者的另一方行动；开局用房间先手，特殊放置不改上一普通行动者 |
| 时间轨道 | 起点 0、终点 53；超过终点截断 |
| 纽扣点 | 4、10、16、22、28、34、40、46、52 |
| 特殊拼布点 | 19、25、31、43、49 |
| 经过区间 | 排除出发格，包含落脚格，即 (旧位置, 新位置]；先截断终点 |
| 特殊拼布 | 1×1，免费、无时间成本、无收入；首次经过者领取，先处理待放再继续普通行动或计分 |
| 满图版特殊拼布 | 自动弃置已领取的特殊拼布并记录原因；不退回、不转交对手 |
| 7×7 奖励 | 全局首位完整覆盖连续 7×7 区域获得 7 分，唯一且不能花费 |
| 终局计分 | 剩余纽扣 + 7×7 奖励；空格扣分为 0；等分平局 |

同格换人、不扣空格分，以及“平局/满图版弃置”均已由用户确认。轨道数值采用当前项目代码中的布局，不补入第 37 格，不把本版本宣称为其他规则版本的复刻。后续如调整这些数值，必须建立新的规则版本。

可执行规则示例：A 普通行动后与 B 同格，下一普通行动者为 B；5 纽扣无奖励得 5 分，有奖励得 12 分；从 50 移动到 57 按终点截断，只经过收入点 52。T37 已实现完整移动扣费、奖励颁发、特殊拼布领取/放置与自然结束结算。

## 拼布数据迁移与校验

来源是 [旧 new_patches()](../src/new_game/patches.rs) 的实际初始化表。旧 bt 没有已实现的结算调用方；本次按本项目定义明确映射为 bt.0 → button_cost（价格），bt.1 → time_cost（时间），button → income（收入），并保留全部原数值。不是把另一个 Patch::new() 的测试用零值写入正式规则。

旧形状按每行 3 格解码：x = index % 3，y = index / 3，再移除坐标起点的空白偏移。迁移后仍为 **33 块、166 个占格**；唯一起始拼布为 **ID 10，价格 2、时间 1、收入 0**。

ID 1–33 在本次冻结时分配，恰好对应旧表序号加一；以后不按 Vec 下标取定义，也不因排序、洗牌或取布而重编号。相同形状可以有不同价格/时间/收入，不能按形状去重。例如 ID 5 与 ID 20 的形状相同而数值不同。

校验涵盖：总数、缺失/重复/越界 ID、至少两格的普通拼布、坐标唯一与范围、归一化、正交连通、正时间成本、唯一 1×2 起始拼布、轨道点严格递增/不重复/不越界。特殊 1×1 定义单独保存，不混入普通供给表。

## 规则版本与快照兼容

| rules_version | 注册状态 | 当前开局行为 |
|---|---|---|
| v1 | 旧空对局的兼容名称 | 允许现有空对局 |
| friend_room_empty_v1 | 显式空对局名称 | 允许现有空对局 |
| patchwork_custom_v1 | 定义、核心行动与 T38 权威事务已实现 | 允许正式开局，服务端初始化并保存实际随机排列 |
| 其他字符串 | 未注册 | 创建/改规则返回 INVALID_REQUEST，旧等待房用该规则开局也拒绝 |

创建和改规则在 Actor 请求准备及事务层均校验注册表。开局在锁定房间后重新检查已保存的规则；通用 begin_game/write_game 拒绝正式规则，不能通过整份 JSON 绕过权威初始化或动作。拒绝不能改变准备状态/房间版本、留下 starting 或插入对局。

历史 kind=friend_room_empty_v1 的快照保持原样读取/恢复，不自动转换为正式对局；历史任意规则标签不会因此获得创建新对局的资格。旧等待房可以显式选择已注册规则并重新准备。

正式快照注册的元信息为：

~~~json
{
  "kind": "patchwork_game_v1",
  "rules_version": "patchwork_custom_v1",
  "schema_version": 1
}
~~~

T34 冻结格式标识；T35 已提供 GameSnapshot 正文，T36 已补齐几何和 7×7 依据检查，T37 已完成动作规则；T38 接入服务端持久化。schema_version 是 JSON 格式版本，与 rules_version、数据库 state_version、事件 seq、外层 Protobuf 协议版本分别管理。snapshot_format 只分类元信息，不验证正文是否完整、棋盘是否合法，不能拿其成功结果作为对局有效性证明。正式规则与空对局 kind 混用、缺失 schema、未知 schema 或未知正式规则的组合均拒绝。
